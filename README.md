**Quick reproduction**

```bash
python3.12 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python reproduce.py
```

The command above regenerates tables, statistics and four figures in `results/`, checking them against the final study. No downloads, models, GPU or Arrow are needed. `.venv/bin/python check.py` checks labels and integrity.

Implementation: `openlibrary/`. Source versions, checksums, models and resources: [sources.json](sources.json), [pipeline.json](pipeline.json).

**Full reproduction:** set `WORK` to a large working directory and run within an HPC batch allocation:

```bash
.venv/bin/pip install -r requirements-full.txt
.venv/bin/python full.py --workdir "$WORK" --check
.venv/bin/python full.py --workdir "$WORK" --stage all
```

`all` acquires the checksum-verified 30 June 2026 dumps, constructs the corpus, retrieves and samples candidates, recomputes annual counts, restores annotations only to identical evidence and regenerates results. Dumps are excluded. Original aggregation used 1,000 GiB RAM; allow hours and substantial scratch space.

Run stages separately with `--stage acquire|prepare|retrieve|temporal|evaluate`. Modify the referenced configurations and source manifest for new data. A changed sample requires new human labels:

```bash
.venv/bin/python -m openlibrary.annotate \
  --packet "$WORK/openlibrary/packet/evaluation_primary_100_blinded.csv" \
  --output "$WORK/annotations.csv"
.venv/bin/python full.py --workdir "$WORK" --stage evaluate \
  --annotations "$WORK/annotations.csv"
```

This produces new-sample statistics; follow the codebook for annotation and delayed retesting.

The quick/full commands use included Qwen predictions unless GPU inference is explicitly rerun. Install `requirements-secondary.txt` in a separate environment, then run `python full.py --workdir "$WORK" --stage llm` followed by `--stage evaluate` in the main environment; the original runtime used GH200/vLLM 0.19.1.
